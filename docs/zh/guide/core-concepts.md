# 核心概念

理解下面五点，就能看懂 ReliaForge 如何运行插件。

## 每个插件都有一份说明文件

每个插件都有一个 `manifest.json`，其中写明 ID、版本、依赖、提供的服务和 Python 入口。
ReliaForge 会先检查所有说明文件，再导入插件代码。某个插件损坏时，它和依赖它的插件会被标记，
无关插件仍然可见。

## 运行状态和健康状态回答不同问题

运行状态说明 ReliaForge 已经执行到哪一步：

```text
discover -> validate -> initialize -> start -> stop
```

健康状态说明已加载插件当前是健康、降级、出错还是已停止。健康检查只读取内存中的当前状态，
不会顺便修复外部系统。

## 插件通过名称共享服务

插件可以用 `demo.greeting` 这样的名称提供服务。另一个插件把提供者写入依赖，再向 ReliaForge
获取服务，而不是直接导入对方的 Python 内部模块。

## 一个设置类定义全部配置

插件的 Python `PluginSettings` 类负责读取环境变量，也定义控制台展示哪些配置项。插件目录 API
不会返回密钥值或密钥默认值。

## 后端决定当前可以执行哪些操作

每个插件响应都包含 `available_actions`。后端根据插件当前状态和依赖计算这个列表，控制台只负责
展示。值班人员点击操作后，API 仍会认证并重新检查请求。

插件会作为受信任的 Python 代码在后端进程内运行。请只安装经过审核的插件。
