# 路线图

ReliaForge 根据真实插件和操作者需求成长，而不是照着平台功能清单扩张。

## 当前可用

- 类型化清单发现和完整依赖图校验；
- 确定性的依赖排序与生命周期管理；
- 提供者拥有的服务和隔离失败的本地事件；
- 以 Python Settings 作为公开配置形状的来源；
- 只读健康与目录 API，以及经过认证的生命周期操作；
- 两个中立示例插件和可复制的脚手架；
- 可选的通用 React 控制台；
- 在线只读控制台演示和公开项目文档。

## 可能的下一步

- 使用公开脚手架开发一个第三方插件，并根据实际摩擦改进契约；
- 根据真实、可复现的环境编写部署方案；
- 依据真实外部使用情况完善 API 和插件兼容策略；
- 在不增加隐藏基础设施的前提下，改善贡献者示例和失败诊断。

## 需要证据才能推进的设想

以下只是可能性，不是承诺：

- 更丰富的插件自有界面扩展点；
- 为特定工作负载提供隔离执行边界；
- 由显式适配器负责的持久化事件或任务集成；
- 可发现的插件索引；
- 一键式云开发环境。

任何设想进入实施计划前，都需要具体用例、清晰所有权、失败语义、安全分析和测试。

## 明确不包含的能力

ReliaForge 当前不承诺托管式多租户服务、内置监控数据库、告警套件、持久工作流引擎、
不受信任代码沙箱或插件市场。
