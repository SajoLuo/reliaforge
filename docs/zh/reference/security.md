# 安全模型

ReliaForge 默认允许读取状态，但会认证所有能够改变插件状态的操作。

## 只读接口

存活、就绪、平台状态、插件列表和插件详情只读取当前内存状态，不会修复插件，也不会返回配置值。
配置说明会显示字段名称和类型，但不包含密钥值和密钥默认值。

## 受保护的操作

调用插件 API 或启动、停止、重启插件时，后端都会验证操作者身份。`available_actions` 只告诉控制台
哪些操作符合当前状态，并不代表已经授权。后端会重新认证和检查每次请求。

## 本地开发

只有在开发或测试模式下，并且后端绑定到回环地址时，才允许匿名管理。CORS 必须列出允许浏览器访问的
具体来源，包括协议、主机和端口。该模式只适合可信工作站，不能用于共享服务器。

## 生产代理认证

生产环境需要：

- 地址范围有限的可信代理网络；
- 只接受该代理提供的操作者身份请求头；
- 代理和后端之间使用高强度共享密钥；
- 网络配置能够保留代理的直接 TCP 地址。

配置不完整时，后端会拒绝启动。生产环境还会关闭交互式 API 文档。

## 浏览器与插件信任

前端不保存管理密钥，浏览器构建变量都是公开信息。生产代理在服务端认证操作者并添加身份。

插件会作为受信任的 Python 代码在后端进程内运行。安装前请审核插件；ReliaForge 不会隔离
恶意插件代码。

[在线演示](https://demo.reliaforge.dev/#/zh/)没有后端，也不会发送管理请求。发现疑似漏洞时，
请按照仓库的 `SECURITY.md` 私下报告。
