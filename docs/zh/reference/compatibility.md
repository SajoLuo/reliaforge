# 兼容性与版本

ReliaForge 的初始公开兼容面经过刻意收敛。

## 插件 API 版本

初始运行时接受 `api_version: "v1"`。不支持的版本会在清单校验阶段、入口点导入之前被拒绝。

## 插件依赖

依赖使用包含插件 ID 和可接受 SemVer 范围的对象。导入开始前，系统会在完整依赖图上检查提供者
缺失、版本不兼容和循环依赖。

提供者插件的 SemVer 是能力兼容边界。服务注册不会携带第二套独立版本。

## 管理 API

控制台使用 `/api/v1`。运行时响应解析器会在浏览器边界拒绝未知的生命周期状态、健康状态、操作
或格式错误的摘要。后端模型和前端解析器的变更应同步落地，并通过跨仓库契约检查。

## 设置

插件设置使用规范的 `RELIAFORGE_<PLUGIN_ID>_` 前缀和 `__` 嵌套分隔符。重启会为已加载插件
重新构造设置，但不会从磁盘重新加载 Python 源码或清单。

## 不承诺兼容旧插件

公开项目从当前清单、依赖、能力和 Settings 契约起步，不携带早期私有插件格式的兼容层。
只有当已发布的公开契约拥有真实使用者，并且存在明确迁移路径时，才会增加兼容性。
